Your source code is your intellectual property, and your repositories hold much more: names, emails, design decisions, security findings and sometimes regulated data. European rules increasingly ask where that data lives, who can reach it, and whether you could leave.

GitHub Enterprise Cloud with data residency, known as **GHE.com**, can store your code and its history in GitHub's EU region, which includes Norway and Switzerland. This guide links to primary sources and explains the limits of the commitment.

## The answer in 60 seconds

- **What stays in the EU region:** repositories, pull requests, issues, Actions data and logs, backups, and user identity data ([GitHub's storage page](https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/about-storage-of-your-data-with-data-residency)). This region includes Norway and Switzerland.
- **What can leave:** a documented set of categories, including telemetry, billing, support data and some opt-in features. Each one needs a decision, not a surprise.
- **Copilot:** the residency policy keeps supported inference processing in the selected region. It is off by default and adds 10% to AI credit consumption ([Copilot with data residency](https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/github-copilot-with-data-residency)).
- **Contract:** the [GitHub DPA](https://github.com/customer-terms/github-data-protection-agreement) makes your region choice a processing instruction and adds transfer safeguards.
- **What it is not:** full sovereignty. GitHub is a US company, so residency is location plus contractual protection, not immunity from foreign law.
